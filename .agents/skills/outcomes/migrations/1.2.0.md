# outcomes@1.1.0 → outcomes@1.2.0

This is a minor bump under the template's skill-version rules: the skill now
requires the produced disposition and explicit task identity before a sig-
draft's first format check. The feature-map rule from 1.1.0 is unchanged.

A stamp records the versions that wrote a contract. Historical contracts keep
their outcomes@1.1.0 (or earlier) stamp unless the producer actually revalidates
them. A differing installed version is warned about, not automatically refused;
that does not waive the independent sig- provenance gate. Do not bulk-restamp
or merely replace a version token to make an audit quiet.

When revalidating a previous draft or repairing a refusal:

1. Load the current intent and outcomes skills into a fresh producer brief;
   preserve active work before the commander refreshes a standing producer.
   Re-read the supplied intent and revalidate every outcome with these skills,
   including the feature-map comparison. Keep the real trace, signal and task
   identity rather than inventing replacements.
2. For a `sig-` draft, read the roster producer name and inspect the existing
   intake row. If still open, record its disposition before checking:
   `BEADS_ACTOR=<producer-seat> bun seats/intake.ts dispose <sig-id> produced --work <bead-id>`.
   Reuse a completed `produced` row only if both task and producer match.
   Otherwise stop and route the discrepancy; completed history is not editable
   and a duplicate signal is not a repair.
3. After real revalidation, stamp the draft with `outcomes@1.2.0` and the actual
   intent version used. For a sig- draft run
   `bun seats/contract.ts check --file <contract> --bead <bead-id>` until exit 0;
   it checks the already-recorded produced disposition. For `isa-gap:` or
   `install-procedure` drafts only, use
   `bun seats/contract.ts check --file <contract>`; those paths need no intake
   disposition. Preserve their existing requirements and carve-outs.
4. Run `bun seats/manual.ts lint-contract --file <contract> --repo <repo>` and
   require exit 0 and equal expected/found map counts. Only then apply the
   revalidated contract through the producer's normal graph workflow.

The shipped examples keep their original 1.0.0/1.1.0 stamps: their history is
not a claim that this later authoring sequence was used to write them.
